# سیاست نسخه‌بندی

> وضعیت: فاز ۱.۲ — تثبیت‌شده.
> منبع اجرایی: `crates/aria-contracts/src/versioning.rs`

## چهار نسخه پایدار

| نسخه | مقدار فعلی | نوع | توضیح |
|---|---|---|---|
| نسخه قرارداد کرنل (`KERNEL_CONTRACT_VERSION`) | `1.0.0` | semver | نسخه قراردادهای عمومی (انواع، تریت‌ها، اسکیماها) |
| نسخه API پلاگین (`PLUGIN_API_VERSION`) | `1.0.0` | semver | نسخه API‌ای که پلاگین‌ها با آن سازگارند |
| نسخه اسکیمای دیتابیس (`DATABASE_SCHEMA_VERSION`) | `1` | عدد صحیح | نسخه فیزیکی اسکیما (PRAGMA user_version / refinery) |
| نسخه فرمت پشتیبان (`BACKUP_FORMAT_VERSION`) | `1` | عدد صحیح | نسخه فرمت بسته پشتیبان |

علاوه بر این‌ها، **نسخه پاکت رویداد** (`EVENT_ENVELOPE_VERSION`، مقدار
فعلی `1`) نسخه اصلی شکل بار رویدادها را نسخه‌بندی می‌کند.

## سازگاری

- پلاگین‌ها در مانیفست خود محدوده semver اعلام می‌کنند:
  `kernel_version_range` و `api_version_range`
- کرنل پلاگین را فقط در صورت تطابق **هر دو** محدوده اجرا می‌کند
- کمک‌کننده‌ها:
  - `is_kernel_compatible(range)` — سازگاری با نسخه کرنل
  - `is_api_compatible(range)` — سازگاری با نسخه API پلاگین
  - `check_manifest_compatibility(manifest)` — بررسی کامل مانیفست
    با نتیجه `Compatible` / `KernelMismatch` / `ApiMismatch`
- اطلاعات نسخه‌ها از طریق متد عمومی `kernel.version` در دسترس پلاگین‌ها
  است (`ContractVersions::current()`)

## سیاست رویدادها

- هر رویداد عضو `event_version` دارد (نسخه اصلی شکل بار)
- **تغییرات افزایشی** (افزودن عضو اختیاری جدید) نسخه رویداد را تغییر
  نمی‌دهد؛ مصرف‌کننده‌ها باید اعضای ناشناخته را نادیده بگیرند
- **تغییر شکست‌زا** نسخه اصلی رویداد را می‌افزاید؛ مصرف‌کننده‌ها باید
  رویدادهای همین نسخه و نسخه‌های اصلی قدیمی‌تر را تا پایان دوره
  منقضی‌سازی پشتیبانی کنند (`is_event_version_supported(event, supported)`)
- تغییر شکست‌زا بدون سیاست منقضی‌سازی صریح ممنوع است

## سیاست کلی تغییرات قرارداد

- قراردادها منبع حقیقت هستند؛ پیاده‌سازی داخلی می‌تواند تکامل یابد اما
  قراردادهای عمومی نسخه‌بندی‌شده و سازگار با نسخه قبلی باقی می‌مانند
- در یک نسخه اصلی (major)، کدهای خطا و رشته‌های پایدار دست‌نخورده
  باقی می‌مانند؛ افزودن مجاز است
- ارتقاء قرارداد = افزایش نسخه اصلی + مستندسازی تغییرات + دوره منقضی‌سازی
  برای نسخه قبلی
- سطوح بسته (انواع دستور، انواع رویداد، قابلیت‌ها، نقاط افزونه UI،
  متدهای دفترچه روش‌ها) فقط از طریق این فرایند ارتقاء گسترش می‌یابند
